# DiskVacuum

A fast, visual, local-first disk analyzer and cleanup assistant built with Tauri, Rust, React, and TypeScript.

> DiskVacuum is in early development. Linux is the currently verified platform. macOS builds are configured in CI but still require runtime verification and Apple signing/notarization before a public production release. Windows and Android support are planned.

[Download the latest release](https://github.com/khalids01/disk-vacuum/releases/latest) · [Report an issue](https://github.com/khalids01/disk-vacuum/issues) · [Development plan](docs/todo-progress.md)

## Why DiskVacuum

DiskVacuum helps you understand where storage is going before you remove anything. It combines a responsive disk explorer with conservative cleanup workflows, persistent scan results, protected-file detection, and explicit review before destructive actions.

All scanning and analysis runs locally. DiskVacuum does not upload file names, paths, hashes, or scan results to a remote service.

## Current features

- Scan the full system, home directory, or a selected folder
- Live scan phases, file/folder counts, processed size, and progress indicators
- Persistent, compact scan index that survives application restarts
- Interactive proportional treemap and directory navigation
- Storage totals that distinguish free, user-available, and system-reserved space
- Global indexed search
- Large-file discovery with protected-file filtering
- Duplicate detection using metadata, partial hashes, and content confirmation
- Developer artifact and package-cache discovery
- AI model and tool-storage discovery
- Leftovers from removed applications
- Review-first cleanup with validation and trash support
- Platform-aware onboarding and exclusions
- System, light, and dark themes
- Signed in-app update checks with download progress and restart

## Safety model

DiskVacuum treats deletion as a separate operation from scanning.

- Files are never deleted during a scan.
- Cleanup candidates must pass backend validation immediately before removal.
- Protected operating-system locations are excluded or clearly marked.
- Symbolic links and changed files are rejected by cleanup validation.
- Supported cleanup actions use the operating-system trash where possible.
- Duplicate recommendations keep at least one confirmed copy.
- Automatic cleanup is not enabled yet.

Always review selected paths before confirming cleanup. No cleanup utility can infer the value of personal data.

### Linux installation

For the portable AppImage:

```bash
chmod +x DiskVacuum_0.1.0_amd64.AppImage
./DiskVacuum_0.1.0_amd64.AppImage
```

For Debian, Ubuntu, Linux Mint, Pop!_OS, and related systems:

```bash
sudo apt install ./DiskVacuum_0.1.0_amd64.deb
```

## Development

### Requirements

- Bun
- Rust stable toolchain
- Tauri 2 system dependencies for your operating system

On Debian or Ubuntu:

```bash
sudo apt update
sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file \
  libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
```

Install dependencies and start development mode:

```bash
bun install
bun tauri dev
```

Useful checks:

```bash
bun run check
bun run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

## Building installers

Local signed Linux build:

```bash
cp .env.example .env
# Fill in the private updater key path and password.
bun run release:build
```

Generated installers are placed in:

```text
src-tauri/target/release/bundle/
```

Most other files under `src-tauri/target/release/` are Rust compiler artifacts and are not intended for distribution.

## Versioning and releases

Prepare one aligned semantic-version update:

```bash
bun run release:prepare 0.2.0
```

This updates all application manifests together. After reviewing the changes:

```bash
git add .
git commit -m "chore: release v0.2.0"
git tag v0.2.0
git push
git push origin v0.2.0
```

A pushed `v*` tag starts the GitHub Actions release workflow. It builds Linux plus Intel and Apple Silicon macOS packages, signs updater artifacts, publishes the GitHub Release, and generates `latest.json` for the in-app updater.

The repository must contain these GitHub Actions secrets before the workflow can publish builds:

- `TAURI_SIGNING_PRIVATE_KEY`: complete contents of the updater private-key file
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: password protecting that key

The updater public key is intentionally committed in `src-tauri/tauri.conf.json`. Never commit the private key, its password, or the local `.env` file. See [the complete updater guide](docs/self-updater.md).

For an existing failed tag run, add the missing secrets and select **Re-run all jobs** on the failed GitHub Actions run. Creating another copy of the same tag is unnecessary.

## Architecture

```text
src/
  app/                 providers and application composition
  components/          reusable UI and layout primitives
  features/            feature-owned React UI, queries, and stores
  routes/              TanStack Router file routes
src-tauri/src/
  features/            scanning, analysis, cleanup, settings, and system logic
  app_state.rs         managed application state
  scan_repository.rs   compact durable scan index
```

The frontend uses React, TypeScript, TanStack Router, TanStack Query, Zustand, Tailwind CSS, and shadcn-style components. Rust owns filesystem traversal, persistence, hashing, protection rules, and cleanup validation.

## Contributing

This project is moving quickly. Before submitting a change:

1. Keep filesystem and cleanup behavior conservative.
2. Add Rust tests for scanning, indexing, hashing, or deletion-policy changes.
3. Run the frontend and Rust checks above.
4. Test platform-specific behavior on the target operating system.

Bug reports should include the operating system, DiskVacuum version, scan target, and reproduction steps. Do not include private file paths unless they are necessary and sanitized.
